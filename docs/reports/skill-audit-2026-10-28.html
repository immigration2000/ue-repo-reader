02 / 높은 분석력의 구체적인 의미

설명에 필요한 정보가 끝까지 연결되어야 합니다

토큰이 적은 작업부터 고르는 순서를 바꿨습니다. 우선순위는 중요한 사실을 놓치지 않는가 → 관계를 맞게 연결하는가 → 프로젝트를 근거로 설명하는가입니다.

  1. 01 / INPUT입력 범위

    프로젝트·에셋 버전, 플러그인, 누락 파일

  2. 02 / VALUES값의 완전성

    저장값·상속·컴포넌트·오버라이드 출처

  3. 03 / IR로직 구조

    실행/데이터 연결, 분기·반환·이벤트

  4. 04 / CONTEXT관계와 맥락

    BP↔C++·입력·설정·데이터·맵

  5. 05 / ANSWERS근거 있는 설명

    사실·추론·미확정을 분리한 답변

  6. 06 / CHECK이해력 평가

    정답 대조·대표 질문·변경 재현

용어: IR은 노드·핀·연결·값을 비교할 수 있게 담은 공통 로직 데이터 형식입니다. CDO는 클래스에 저장된 기본값을 담는 객체입니다. 보기 좋은 요약과 원래 값/관계를 보존하는 데이터는 역할을 나눕니다.

표시를 짧게 만드는 것과 정보를 잃는 것은 구분합니다. 전체 디코딩 값은 보존하고 필요한 부분을 페이지로 조회하는 방향을 우선합니다. 안전한 시간·크기 상한은 유지하되, 넘친 범위나 읽지 못한 기능을 완전한 분석처럼 보고하지 않도록 합니다.
확인된 사실

저장된 핀 연결·값·상속/참조·원본 코드 위치로 확인한 내용. 근거 위치를 함께 제시합니다.

추론

여러 근거를 조합한 해석. 실제 저장 연결과 이름 힌트, 가능성 있는 호출을 구분합니다.

알 수 없음

동적 호출·미저장 기본값·빠진 파일·미지원 포맷 등 확인할 수 없는 범위를 구체적으로 적습니다.

04 / 레포를 잘 이해하는지 평가

Architecture

07 / 현행 검증과 새 보증 범위

기존 검사를 그대로 새 지원 보증으로 세지 않습니다

현재 도구의 검증 이력과 5.7+ 목표의 완료 관문을 분리합니다. 보고서 개정으로 테스트가 제거되거나 새 의미 정답이 생긴 것은 아닙니다.

완료의 기준: 중요한 값·연결·정의 위치가 정답과 맞고, 설명의 근거가 이어지며, 누락/미검증 범위가 표시되어야 합니다. 정적 분석만으로 실행 중 상태·성능·동적 호출의 실제 발생을 확정하지 않습니다. 전체 정확도나 구버전 축소의 절약률은 아직 측정하지 않았습니다.
